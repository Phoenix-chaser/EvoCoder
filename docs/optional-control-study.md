# 执行反馈能形成技能，也能提高修复率吗？

我们分别检查模型写出的技能、后续求解的工具动作，以及独立测试给出的修复结果。GLM 生成了可复用的缺省处理规则。历史轨迹中可观察到部分动作占比变化，本轮开发对照中两臂修复数持平。[冻结协议](../benchmarks/optional_control/protocol.json) · [正向对照收据](results/optional-control.json)

## 一、从已有轨迹测量行为吸收率

重新读取两批已完成的 GLM-5.3 实验，共 16 个父子配对、32 次求解，新增模型调用为 **0**。分析器只读 SQLite，逐条核对任务快照、实际选中的技能、运行状态和修复评分。在固定跳过组，同一配对的两臂首次求解请求哈希完全一致。[逐配对动作计数](results/behavior-uptake.json) · [提取脚本](../scripts/measure_skill_uptake.py)

对每次求解，将模型发出的 `ACTION` 按工具名计数，再除以该次的动作总数。动作包含读、搜、改、命令、测试及提交。路由、运行器自动复验和评测器评分不计入动作，非法动作另列。每个配对的总变差距离为 `TV = ½ × Σ |p候选(动作) − p父版(动作)|`。相同动作比例的长短轨迹距离为零。

**行为吸收率**是满足 `TV(两边注入各自的技能) > TV(两边都跳过技能)` 的同题同轮配对数占比。等于噪声对照记为未超过。每个配对等权。

| 同一批路由实验 | 配对数 | 两边都实际用技能 | 平均 TV | 父版 / 候选修复数 |
| --- | ---: | ---: | ---: | ---: |
| 正常路由 | 4 | 3 | 34.6% | 2 / 2 |
| 固定注入各自技能 | 4 | 4 | 30.1% | 2 / 2 |
| 固定跳过技能 | 4 | 0 | 17.7% | 2 / 1 |

**3/4 配对超过对应的跳过对照，平均距离差为 +12.4 个百分点。** 固定注入时，候选比父版的读取动作占比高 9.0 个百分点，编辑动作占比低 12.8 个百分点。四个配对只来自两道题，每个题轮只有一个噪声对照。这个比例描述动作组合的变化，不能读成“75% 的技能步骤得到执行”。相同工具也可以检查完全不同的行为。

在另一批启用相同开关覆盖反馈的实验中，四个开发配对均实际采用技能。两臂的平均 TV 为 18.2%，各修好 3/4。检查语义时，能在提交补丁上检出关闭侧回归的自写断言由 1/4 增至 2/4。这批没有同协议的固定跳过组，因此不给它计算噪声校正后的吸收率。已有证据说明某些动作和检查确实变了，修复数持平仍可能来自技能内容、执行波动或任务难度。[开关实验](click-switch-feedback.md)

## 二、把已知有解的任务做成正向对照

50 个实例由 **10 个独立编写的业务适配器模板 × 5 种设置类型**生成。类型覆盖数字、布尔、文本、列表和映射，损坏代码、公开测试以及独立评分都能实际执行。整个模板只进入一个分区。实例是生成的业务契约，来自相同模板的五个实例共享实现结构。[生成器](../src/evocoder/optional_benchmark.py)

| 分区 | 实现与用途 | 实例 |
| --- | --- | ---: |
| 学习 | 任务调度、导出清单。4 次无技能修复供提案，另外 6 次按正常路由试用 | 10 |
| 开发 | 网关配置对象、审计记录更新。比较无技能与学得技能 | 10 |
| 留出 | 缓存及报表的单值覆盖、通知及渲染的多层优先级、事件及检查点的批处理 | 30 |

冻结协议前，在固定镜像中对每题分别执行损坏版、参考修复及把所有假值都当成缺失的误修版。公开测试和独立评分分别在新 Python 进程中运行，总计 300 次，**50/50 题符合预设条件**。损坏版两项都失败，参考修复两项都通过。误修在 10 道学习题的公开用例中暴露，在 40 道开发及留出题上通过公开用例，但全部 50 道的独立评分都能将它检出。这里只做了题目校准，留出源码和评分结果没有进入学习证据。

模型只看到问题、仓库文件和公开测试。求解、技能提案和路由都走真实 GLM 接口。普通提案器从学习运行提取公开补丁和工具反馈，模型自行生成技能字段。参考实现、误修版、独立评分用例及人工参照技能留在评测端。参照技能在单独的状态库中强制注入，仅用于错误定位。

## 三、模型学到了什么，收益停在哪里

四次无技能学习修复都成功。GLM 从四条轨迹生成了根技能 `restore-default-on-null-override`，要求先核对缺省与显式 null 的契约，只对缺失值应用预设，并验证合法的 `0`、`False`、空字符串能保留。后续六道学习题都经正常路由采用了它并通过。没有出现符合协议的父版应用失败，因此本轮形成了根技能，未生成子版。[模型原始技能字段、证据引用与评分](results/optional-control.json)

| 第一轮开发对照 | 无技能 | 学得技能 |
| --- | ---: | ---: |
| 独立评分通过 | 10/10 | 10/10 |
| 在提交补丁上同时通过缺失与合法假值的单独复验 | 10/10 | 10/10 |
| 实际注入技能 | 0/10 | 10/10 |
| 发出的求解动作（含提交） | 54 | 60 |
| 模型调用（含路由和非法响应） | 55 | 73 |

两臂各有 15 个求解动作名额。技能臂另外留 1 步给语义路由，空技能臂在同一位置保留空槽，不发模型请求。每个配对从相同快照开始，先后顺序交错。该批样本中，技能臂多用 18 次模型调用，修复率差为 **0 个百分点**。预先选定的两个开发实例上，人工参照技能为 2/2，无技能也为 2/2。**GLM 从执行反馈生成并应用了目标规则。这两类开发实现上的无技能基线已经满分。** 提案能写出规则，和模型原本就了解 Python 假值语义，两者可以同时成立。

发布要求至少两个开发组中各有同一道题两轮都出现“候选修好、基线失败”，且开发与支持回放无退化或基础设施错误。第一轮全部十题都跑完后，可继续满足两轮改善的分组数已经是 0。后续重跑同一批无法补出第一轮胜例，流程提前结束。候选未发布，留出求解记录和共享账本中的留出题暴露数均为 0。

**收益随多样性的变化仍待测量。** 协议已冻结三个等权混合点，分别纳入单值覆盖、再加多层优先级、再加批处理。仅在通过完整门禁后，才用冻结技能和无技能基线分别求解 30 道留出题。绘图器使用各混合点实际的配对修复率差，数据同时保留单族差值，允许上升、持平或下降。三个点共用前面已纳入的配对，引入新任务族也会改变难度。未来即便观察到下降，也只能据此描述这三种任务组合。当前没有留出观测。

本轮共 205 次 GLM 调用，按本地配置费率记 158.11432 套餐积分，本轮新增未结算预留为 0。历史动作诊断、独立补丁复验与制图均使用已存证据。

后续实验单独校准了**任务对技能的区分度**。三个上游缺陷和一个队列配置案例构成预试集，与新开发题分开。研究先比较无技能与人工参照，观察到可重复纠正的错误后，再评估这里生成的同一份根技能。[预试和新开发对照](falsy-transfer-study.md)

## 复核与复现

公开的 JSON 保留配对计数、实际注入版本、提案内容、评分和复验结果。以下命令只用仓库内的记录复算指标、核验 50 个冻结快照并检查门禁与留出状态，无需模型密钥。逐补丁重新执行复验另需本地原始归档。

```bash
uv run --locked python scripts/report_optional_control.py verify
```

本机具备 Docker 及 Python 3.12 镜像时，可以零模型调用重跑 300 个校准检查。保留了原始本地 SQLite 归档的环境也可从头提取历史诊断，或用 `export` 从原始补丁重新执行缺失和假值检查。

```bash
uv run --locked python scripts/report_optional_control.py calibrate --image python:3.12-slim
uv run --locked python scripts/measure_skill_uptake.py --output experiments/uptake-replay.json
uv run --locked python scripts/report_optional_control.py export \
  --root experiments/optional-control-001 --result experiments/optional-replay.json
```

独立的真实复现使用新的目录和已配置的 GLM Coding Plan 累计账本。`prepare` 要求 `EVOCODER_IMAGE` 为本机镜像的不可变 image ID。`run` 才会发起模型调用。中断后同目录续跑会复用已完成的题、实验臂和轮次。已发出但状态不确定的请求保留原账本记录。

```bash
uv run --locked python scripts/run_optional_control.py prepare --root experiments/optional-replication
uv run --locked python scripts/run_optional_control.py run --root experiments/optional-replication
uv run --locked python scripts/report_optional_control.py export \
  --root experiments/optional-replication --registration experiments/optional-replication/protocol.json \
  --result experiments/optional-replication/public-result.json
uv run --script docs/results/plot.py --study experiments/optional-replication/public-result.json \
  --output-dir experiments/optional-replication/figures
```
