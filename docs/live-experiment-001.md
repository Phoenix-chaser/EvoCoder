# 首轮真实模型实验：接入成功，尚无进化收益证据

实验日期为 2026-11-15。模型采用固定权重的 `deepseek-flash`，关闭 thinking，费用按独立实验账本计量。

## 实际完成内容

1. 首次连通因模型函数调用合同不匹配停止，已计费记录保留。最初没有保存具体调用数量和名称，不能倒推其确切原因。
2. 人工明确 `submit_action` 是唯一函数、read/write 等是动作字段，并增加仅含函数名/调用数量的安全诊断；重跑完成一个合成任务。这是工程修复，不是自动技能进化。
3. 从 CodeAgent-R 的 `hard_tasks.py` 冻结 8 个已有自建任务：learn 4、dev 2、test 2，启动前用可信参考代码逐例验证评分环境。参考代码不进入求解器或提案器。
4. 实际调用真实模型执行任务、生成技能、运行配对比较和冻结后的 test；没有修改生成的技能，也没有放宽门禁。

## 这轮暴露的实验设计问题

1. 这些任务对当前模型过于容易，基线达到该小样本的上限，没有改进空间。
2. 生成的是缓存专用技能，而 dev 测的是依赖检测和深合并，能力相关性不足。没有增益既不能证明缓存技能有用，也不能判定整个方法无效。
3. 题目为已有自建案例，开发者已知，不属于自然 issue、SWE-bench 成绩或未见独立终评。source group 不重叠不等于已经证明语义独立。
4. 该技能部分建议超出任务编辑权限，例如建议修改不可编辑的 store；缺失版本时用默认值也可能掩盖不支持的场景。本轮没有验证这些泛化建议，不能直接推广到真实工程。
5. 只有 2 个 dev 和 2 个 test 任务，没有四组基线、多顺序重复或统计结论。

下一阶段应围绕明确可迁移的同一能力建立多个独立仓库任务，同时加入不适用情形；先测出真实基线失败结构，再比较冻结技能与反馈修订。不能通过故意降低模型能力、修改成功标准或手工安排候选获得提升。
