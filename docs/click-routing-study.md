# Click 两道题的路由归因

上轮 GLM 实验中，计数选项题和 Click #557 在重复运行时出现了相反的父子胜负或路由决定。本轮固定父版 `325c34af9897`、子版 `44f5b7395bfd` 和两个开发快照。每次只给路由器一个技能版本，它选择是否向求解器注入该版本。应用技能后求解器会收到整张技能卡，包括操作步骤、验证方式和修订摘要。

## 同一输入为何出现两种路由

对上轮 8 条正常路由的归档检查覆盖任务原文、适用条件和排除条件、程序绑定的版本、模型实际返回的整数选择、引用的原文以及请求用量。在每个题目和版本内，两次记录的输入哈希、提示词哈希和提示 token 数相同。根据冻结的适配器离线重建，四组各自的两次请求正文也相同。旧归档保存了输入证据和返回结果，历史网络请求的逐字节比较依赖这次离线重建。新运行另外保存实际派发正文的规范化哈希。

| 已暴露开发题 | 父版两次选择 | 子版两次选择 | 两种解释的分界 |
| --- | --- | --- | --- |
| 计数选项 | 跳过、应用 | 应用、跳过 | 删除隐式取值范围的内容，还是处理帮助文本的可选后缀与分隔符 |
| Click #557 | 应用、应用 | 跳过、应用 | 增加动态帮助提示，还是按条件插入提示行并保持空行 |

所有选择都通过了路由合同，应用或跳过的结果与实际注入一致。模型为 GLM-5.3，温度为 1，思考强度为 low。两次决策的理由反映出模型给上述两种解释赋予了不同权重。服务端指纹为空，原记录无法单独识别采样、缓存或后端变化的各自影响。#557 父版两次都注入同一技能，第一次通过、第二次失败，已可观察到求解阶段的波动。历史路由证据 `experiments/glm-click-routing-matrix-001/historical-routes.json`

## 正常路由与固定干预

每道题、每种策略、每个版本各求解两次。两次交换父子调用顺序，并轮换策略顺序。固定干预保留一个路由预算步，三种策略均最多有 15 次求解调用。模型、温度、可编辑源码、沙箱镜像、公开测试与独立评分器相同。

| 策略 | 求解器收到的技能 | 能检验的现象 |
| --- | --- | --- |
| 正常路由 | GLM 根据任务选择是否注入 | 实际使用策略时的通过数、注入次数及翻转 |
| 固定应用 | 父臂总是收到父技能，子臂总是收到子技能 | 控制是否注入后，两份技能内容的表现 |
| 固定跳过 | 父子两臂均收到空技能列表 | 相同首步输入下独立采样的结果波动 |

固定应用与固定跳过通过同一个正式求解器执行。干预标签仅保存在控制器事件中。新归档可验证同题且实际注入内容一致时，首个求解请求的规范化哈希是否一致。后续请求依赖各自产生的操作、代码和工具输出。

两道题都已用于开发。固定策略用于归因，正式门禁只使用正常策略。原协议共有三个开发分组，要求其中至少两个分组各重复改善两次，并且开发与学习支持回放零退化。若两道焦点题均未产生重复改善，剩余一个开发分组已无法满足门槛。若正常路由已有退化，同样停止新增任务求解。只有仍有可能通过时才补跑其余开发、历史回归和支持回放。全门禁通过后才运行在本地从未暴露的两道留出题。

## GLM-5.3 实测结果

2026-11-19 完成 12 对开发运行，共 24 条可评分轨迹。每种策略含两道题、每题重复两次。下表中的胜负按同题、同一轮父子配对统计。每格分母为 4。

| 策略 | 父版通过 | 子版通过 | 子版独有成功 | 父版独有成功 |
| --- | --- | --- | --- | --- |
| 正常路由 | 2/4 | 2/4 | 1 | 1 |
| 固定应用各自的技能 | 2/4 | 2/4 | 0 | 0 |
| 固定跳过，两臂均无技能 | 2/4 | 1/4 | 0 | 1 |

每个版本、每种策略内部的结果如下，顺序均为第一次、第二次。

| 题目与策略 | 父版 | 子版 |
| --- | --- | --- |
| 计数选项，正常路由 | 应用失败、跳过通过 | 应用通过、跳过通过 |
| 计数选项，固定应用 | 通过、通过 | 通过、通过 |
| 计数选项，固定跳过 | 通过、通过 | 通过、失败 |
| #557，正常路由 | 应用失败、应用通过 | 应用失败、应用失败 |
| #557，固定应用 | 失败、失败 | 失败、失败 |
| #557，固定跳过 | 失败、失败 | 失败、失败 |

计数题第一次正常求解时，两边都得到了各自的技能。父版首次跑过了 93 项公开测试，随后又修改源码，引发 4 项失败，最后遇到缩进错误，步数用尽。子版通过了公开检查并提交了通过独立评分的补丁。第二次两边都跳过技能并通过。该题第二次固定跳过的两臂收到相同的首个求解请求，却一过一败，直接观察到了与技能注入无关的求解波动。

#557 第二次正常求解时，两边也都使用了技能。父版调用 `get_help_option(ctx)` 检查命令实际提供的帮助选项，子版根据 `ctx.help_option_names` 是否有名称决定是否添加提示。命令关闭帮助后仍可以保留默认的选项名。这两份补丁来自同一条正常策略下的真实退化配对。

原门禁要求三个开发分组中至少两个出现连续两次与技能行为相关的改善，并且零退化。计数题改善一次，#557 退化一次，两道题贡献的重复改善分组为零。按预先冻结的规则提前结束门禁，留出题运行次数为零。两次重复、独立采样和一次跨恢复窗口的配对，只支持本次开发题的归因，不足以估计新题收益。

本实验累计登记 288 个 GLM 请求，用量估算已结算 560.00963 套餐积分。其中的 24 条有效求解之外，还有一条在 HTTP 429 中断的子版尝试。其前两次调用已结算 1.81050 积分并包含在上述合计，第三次仍有 30.74358 积分预留。恢复时保留原父版终态，从同一开发快照重启受影响的子臂。原父版只计分一次。冻结协议 `experiments/glm-click-routing-matrix-002/protocol.json` · 逐对结果及门禁 `experiments/glm-click-routing-matrix-002/result.json` · 中断与结算 `experiments/glm-click-routing-matrix-002/retry-events.json`

### 已提交补丁的独立复验

21 次提交对应 19 份不同补丁。每份补丁都在冻结的 Docker 镜像里重跑独立评分，21 次提交映射回原判定均一致。其余 4 条运行包括 3 次耗尽步数和 1 次 HTTP 429，均没有提交可复验的补丁。复验结果、命令和逐项输出 `experiments/glm-click-routing-matrix-002/patch-probes.json`

- **#557 的正常路由退化可以复现。** 用 `add_help_option=False` 创建命令并触发缺少参数错误。父版成功补丁保留 usage、一个空行、错误消息。子版失败补丁额外打印了 `Try "inspect --help" for help.`，向用户推荐一个已经关闭的选项。#557 的 9 份已提交且独立评分失败的补丁，在这个禁用帮助的场景下都与上游输出有差异，其中 7 份错误显示提示，1 份漏了空行，1 份多了空行。默认帮助、自定义帮助名称和嵌套命令三个公开对照场景均匹配。
- **固定跳过也能产生一对胜负。** 计数题第二次固定跳过时，父版修改帮助记录中的范围处理并通过。子版改了数值类型的 `get_metavar`，计数标志仍显示 `[x>=0]`，还把有显式范围的普通选项类型标签从 `INTEGER RANGE` 改成了 `INT`。两次求解的第一个请求正文相同，后续搜索与编辑已经分叉。
- **通过本题评分的补丁也有兼容性差异。** 4 次通过的运行合计生成两份不同补丁，都以 `and not self.count` 跳过所有计数选项。对显式配置 `count=True, type=IntRange(1, 5)` 的计数选项，这两份补丁把应保留的范围也隐藏了。此项按上游修复额外检查，单列于工单的四个公开场景和正式门禁之外。[计数选项上游提交](https://github.com/pallets/click/commit/3d029e03eb2a793c64166cb1b690cd63e42461af)

下一轮修订值得检验的假设是，技能若引导求解器分别运行“功能开启、功能关闭”两条实际 CLI 命令，并保留此前通过的源码作为可回退点，或许能减少这两类失败。新的学习任务可以提供这种修订的执行证据，本轮两道开发题保留原角色。

## 在本机核对

从仓库根目录运行。第一条命令从原始八条路由重建历史记录。第二、三条命令从本轮已关闭的实验库导出配对报告，再对照运行库和积分账本核验。最后一条使用冻结的 Docker 镜像复验两道开发题的已提交补丁，并比较 CLI 输出中的空格、空行、选项边界和命令路径。四条命令均无需模型调用。输出使用新目录以保留原记录。

```bash
review_dir=$(mktemp -d)
study=experiments/glm-click-routing-matrix-002
uv run --locked python scripts/audit_click_routes.py --previous experiments/glm-click-grounded-001 --output "$review_dir/history.json"
uv run --locked python scripts/report_route_study.py --root "$study" --output "$review_dir/report"
uv run --locked python scripts/verify_route_study.py "$study" "$review_dir/report"
uv run --locked python scripts/probe_click_route_patches.py --root "$study" --output "$review_dir/probes.json"
```
