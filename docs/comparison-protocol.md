# 真实模型四组实验协议

日期：2026-11-17。目标是检验执行反馈引起的技能修订能否改善后续未见缺陷修复。本次是有预算上限的探索实验，不保证得到正结果。

## 数据与适用范围

从九个已下载上游仓库的历史中，按修复提交同时修改源码与回归测试的规则形成 222 个候选。先完成模型无关的环境与原始缺陷验证，221 个未被旧实验直接使用的候选中 96 个合格；每个案例保留失败/排除原因。

再排除修改函数重叠的案例，对最大仓库设 26 例上限，形成 7 个仓库共 80 个缺陷。按各仓库的修复时间划分 learn 32、dev 16、test 32；固定来源提交、快照哈希、修改函数和补丁指纹。分区内配额和多余候选选择的哈希盐已在模型调用前确定。80 例最终快照的原始/参考实现重新验证全部通过。

验证要求原源码在隐藏上游回归中出现真实断言失败，参考源码通过隐藏回归和旧公开测试；JUnit 必须有实际执行的测试、没有收集/导入错误。原公开测试可以通过或断言失败，不要求旧测试已经覆盖新缺陷。

问题描述使用开发者的修复提交说明，不是原始 issue；源码为选定包的 UTF-8 Python 文件，公共测试为旧测试，评分使用修复提交里的上游测试。只覆盖现有 Python 3.12 文本沙箱能复现、测试耗时在限制内的案例，存在选择偏差。不是官方 SWE-bench，不保证无预训练污染，也不代表任意生产仓库。

设计审查确认，上述 80 个历史案例的旧求解请求携带统计分组字段，字段包含从上游修复补丁提取的改动位置。旧结果适用于分析带定位提示的修复过程。新版只投影问题描述、仓库、文件清单、可编辑范围和公开测试命令。分组和基于修复提交生成的任务 ID 保留在控制端，历史轨迹的提案投影也执行同一白名单。新版正式协议要求新输入策略下生成的历史与种子轨迹，旧收据仍可离线复核。

本轮各分区包含相同仓库但不同修改函数，检验同仓库内跨缺陷迁移。没有独立跨仓库终评，不宣称跨仓库泛化。近似缺陷的语义重复仍需额外人工审计；函数与精确补丁去重不能保证完全独立。

## 四组与主要问题

| 组 | 测试时可用信息 | 学习策略 |
|---|---|---|
| A | 无经验 | 基础求解器 |
| B | 冻结历史公开执行轨迹 | TF-IDF 按问题文本检索，最多三条；不含权威评分 |
| C | 通过门禁的初始技能库 | 复用共同初始版本，禁用修订 |
| D | 通过门禁的最新技能库 | 初始版本相同，允许依据后续公开失败修订 |

主要比较为 D−C；D−A、D−B 为辅助比较。为了隔离修订作用，本次先共同积累一批初始根技能，再冻结新增根分支；C/D 的后续差别仅是是否允许修订。不能把本次称为无限制的开放式多分支进化实验。

共同历史先由 A 在 32 个 learn 任务上独立运行得到，冻结到所有分支中。经验 RAG 只能读取这些公开轨迹。初始根技能使用事先声明的三个学习任务：分别来自 cachetools、more-itertools、Click；不根据成功或失败挑换种子。种子运行无效时明确缺失，不替换另一题。初始技能生成和门禁只执行一次，C/D 从相同 SQLite 快照克隆，因此技能内容、证据、已发布库和初始候选完全一致。

预跑 `comparison-live-001` 已完成 32 个共同历史运行，在初始门禁因错误函数名等执行合同问题停止，未调用任何 test 题。原始结果为 13 次 COMPLETE、5 次 FAILED、6 次 EXHAUSTED、8 次 ERROR；费用估算 0.37262610 USD。修复后的下一轮显式复用其中 24 个符合经验合同的公开轨迹，避免重复付费；其余八次错误仍保留。冻结历史数据库和运行哈希，旧运行器的历史不当作新运行器的修复成绩。共用语料和种子 ID 对 C/D 完全相同，不因错误重新挑选种子或测试题。

`comparison-live-002` 完成三个初始根技能及其 102 次门禁修复运行；三个候选均被拒绝，分别有一例退化。随后 C 完成 32 个学习任务，D 在第六题因输出截断的无效决策停止；估算费用 1.073266752 USD，仍未执行 test。第三轮复用已经冻结的共同语料和初始技能快照，并在新版本下重新执行 C/D 学习与终评，保留第二轮所有失败，不用它的 C/D 学习成绩替代新运行。初始技能快照只允许预先声明种子的根技能，不能偷偷导入后续修订版本。

C/D 随后按相同学习顺序实际运行。C 禁止技能生成和修订，D 最多生成三个修订提案。未发布的候选可在学习阶段试用。D 的父版本必须绑定实际应用失败，候选仍需在全库 dev 和学习支持集回放。真实模式对每道 dev 题做两轮配对。至少两组须有重复确认且与技能使用变化对应的改善，全库保持零观察退化和零基础设施错误。终评只在 C、D 发布库具备同族版本对照时启动。[评测门禁规则](skill-library.md)


这比“C/D 各自从随机生成的不同初始技能开始”更能隔离修订的影响，但目前只有一种学习顺序。顺序稳健性和多个独立技能形成过程的重复，留待后续预算；不会把三次测试采样说成三次独立进化实验。

## 计算与费用

各组使用相同 API 地址、模型别名、输出上限、工具、动作纠错、镜像、16 个总模型步骤和 16 KiB 记忆上限。语义路由占一个模型步骤，RAG 是固定的本地检索；记录实际 token、模型决策和费用。共同历史与初始技能形成费用单列；C/D 后续学习和门禁费用单列；终评每次成功修复费用另列，不能忽略技能获得成本来宣称更省钱。

预算通过幂等授权记录追加，原有支出和请求记录随账本保留。各组的知识状态独立，预留与结算共用一份账本。运行配置与凭据保存在本地。

首次预跑后核对 [官方价格](https://api-docs.deepseek.com/quick_start/pricing/)，发现高峰价为原配置的两倍。后续按每百万未缓存输入 0.30 USD、缓存输入 0.006 USD、输出 1.20 USD 的最高时段价格计算：请求前一律按输入未命中预留，只有 [缓存用量字段](https://api-docs.deepseek.com/guides/kv_cache/) 为非负整数且命中/未命中之和等于总输入时才采用缓存价，否则按未命中价估算。这在低峰时段也可能高估账单。

费率变化后，可在总额度中保留差额，覆盖历史估算的不确定性。可用预算同时扣除累计估算、未结算请求和价格差额。

执行层修复对四组一致：完整 HTTP JSON 响应且 usage 已结算时，错误函数名、无有效调用或 finish_reason=length 的不可用动作都不执行、不自动补全，只反馈拒绝原因，允许模型在剩余步骤内重新决策；辅助路由的已结算无效输出直接跳过技能。HTTP JSON 本身不完整、usage 无效或传输不确定时仍保留预留并终止，不重发原请求。输入太长时对公开历史作确定性、有哈希标记的截断投影，完整实际执行轨迹不变。这些属于人工工程修复，不计作技能自进化收益。

D 的已结算但未通过合同校验的技能提案计为被拒绝的一次尝试，不保存成可用技能、不重试同一个请求；最多三次提案尝试，失败也消耗该上限。未结算请求、预算错误与证据预检错误仍停止。这样不能靠无限重生成筛出好候选，也不会让一次错误候选破坏当前已发布库。

独立任务最多四路并发，按有界调度逐步派发，不提前排入整个付费实验。模型传输/用量不确定时保留预留并停止派发，不自动重发；预算耗尽时保留不完整结果，不扩大预算或挑选剩余题。

## 冻结终评与统计

冻结源码、配置、镜像 ID、数据清单、公开历史池、C/D 技能库和来源证据。32 个 test 任务、四组、每组每题三次，共计划 384 次修复运行。轮换组顺序，测试期只写运行/补丁/评分记录，禁止修改技能、发布版本或经验池。记录提供商返回的模型名称与系统指纹；固定 API 别名不能独立证明服务端权重完全未变。

成功必须同时通过独立冻结公开测试与上游回归。错误、超时和步骤耗尽均计入记录。包含 ERROR 或 INTERRUPTED 的矩阵保留描述统计，不能支持收益结论。求解器只收到公开执行反馈。

新建协议冻结 `learn_outcome` 策略。已实际应用父技能的 learn/solve 任务提交了编辑，且通过独立公开测试后仍未通过最终评分时，提案器可接收布尔信号并参考公开轨迹修订。评分超时不触发该信号。独立评分的用例、命令和输出留在评分端，dev/test 结果仅供评测。老检查点继承冻结的反馈策略。

C、D 学习结束后，检查两组的已发布库是否只相差同一技能分支的版本替换。D 至少有一个版本须能追溯至 C 的冻结版本，且每次增删均须成对。未满足时以 `no_revised_library` 结束并保留学习结果，终评调用数为零。通过检查后，终评报告还需核实修订版本确实被任务应用过。

先对每题的三次采样求均值，再对配对 source group 做 4,000 次 bootstrap，固定随机种子 20261117，报告 D−C 的差值、95% 区间、改善及退化案例。重复采样不当作新任务。报告需完整覆盖 384 格，至少 20 个配对缺陷组，且主要差值区间下界大于零，才标记“本次冻结分布下支持正向效果”。20 组是保守的探索门槛，不是充分样本量或统计效力保证。相关仓库内的缺陷可能相关，区间不能解释为跨仓库总体保证。

不完整矩阵不能支持正向结论；区间跨零时结论为未证实收益。即便观察到正结果，也不能推断对其他语言、仓库或学习顺序同样有效。

## 运行入口

```bash
# 新环境先建立镜像并从已提交的固定 commit 目录重建数据；目录需为新目录
make comparison-image
make comparison-benchmark COMPARISON_BUNDLE=experiments/comparison-benchmark-NEW

# 本次冻结数据的实际入口（不是覆盖已有输出的命令）
uv run --locked evocoder comparison-prepare \
  --manifest experiments/comparison-benchmark-001/manifest.json \
  --verification experiments/comparison-benchmark-001/verification.json \
  --output experiments/comparison-live-003 --repeats 3 --workers 4 \
  --history-from experiments/comparison-live-001/common \
  --seed-from experiments/comparison-live-002/seed

uv run --locked evocoder comparison-run --output experiments/comparison-live-003
```

协议或启动标记已经存在时拒绝覆盖/重复启动。当前没有自动续跑未完成的付费调用；需要检查调用账本和 intent 后另行处理。若学习或门禁中途失败，会保留已付费用与阶段，不运行终评来装作完成。

### 检查点续跑

第三轮在 D 第七题收到供应商 HTTP 402。恢复时保留原请求的预留，从后续学习任务继续执行。

`comparison-continue-prepare` 接受尚未执行任何 test、被中断学习流尚无修订提案且最后一次实际运行明确为 HTTP 402 或 HTTP 500 的检查点。支持 C 前缀中断（D 必须未开始），或 C 已完成后的 D 前缀中断。求解、路由、提案、门禁和评分代码须与已有学习运行一致。启用输入白名单后的新版，历史定位提示下形成的学习前缀仅供追溯。

后续实验 `comparison-live-004` 克隆共同经验、种子、C 和 D 状态，C 不重复学习，D 保留原七条记录（其中一条 ERROR），从第八题继续。失败的学习任务仍占据原顺序中的位置，不用另一题替换；这是一项明确披露的基础设施缺失，不将 D 的学习记录写成 32 次有效完成。最多三个修订提案、门禁、测试集、16 步预算、模型参数、四组终评与统计口径均不变。所有前序预跑费用计入成本。该入口不是未知超时、部分提案/门禁或终评中断的通用重试功能。

GLM 的 `comparison-glm-004` 从 `comparison-glm-003` 的 C 前十二条记录继续：保留第十二条 ERROR 和对应 42.74130 积分预留，从第十三题开始，不重复共同历史、种子门禁或 C 前缀。C 完成后才从相同种子初始化 D。旧模型终评暴露的跨模型复现声明继续继承；这项续跑能力属于人工工程改进，不属于模型自进化。

```bash
uv run --locked evocoder comparison-continue-prepare \
  --previous experiments/comparison-live-003 \
  --output experiments/comparison-live-004
uv run --locked evocoder comparison-run --output experiments/comparison-live-004
```

`benchmarks/comparison/cases.json` 保留 80 个固定来源及预期清单哈希；`prepare_comparison_benchmark.py` 能重建相同任务快照。本机重新构建 80 例的清单哈希已与冻结版本一致。初次发现/筛选过程见 `mine_benchmark.py`、`verify_candidates.py` 和 `freeze_comparison_benchmark.py`，不需要重新扫描最新仓库来复现本轮。实际镜像安装包版本保存在 `docker/comparison-packages.lock`，执行以离线验证收据的 image ID 为准。

### 终评恢复与历史待核销费用

新版终评在派发前写入含运行 ID 的任务格。明确中断后，在同一个目录调用 `evocoder comparison-run --output 实验目录 --resume-test`。入口重新验证源码、协议、冻结库和共享账本。记录已落库的结果会从运行 ID 还原，进程退出前没写完的运行会标记中断，只有此前没有写入意图的格子会派发。含基础设施错误的完整矩阵仍为无效终评。该入口适用于新协议写出的终评检查点。

开启使用新留出题的协议时，可在 `comparison-prepare` 指定 `--carry-reservations-from 旧实验目录`，必要时多次指定。准备和启动都会核对同一账本上的每一笔未确认调用，要求它能对应到已中止实验的终态运行及原预留。历史未知费用继续占用累计预算。鉴于 GLM 第四轮 C、D 的终评均没有技能库，该轮保留为排查记录，下一轮的修订收益使用新协议验证。
