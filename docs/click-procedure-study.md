# 基于独立学习失败的 Click 技能步骤修订

本轮以此前未发布的 Click 技能 `44f5b7395bfd` 为父版，固定 GLM-5.3、温度 1、16 步预算和 Docker 镜像。公开测试通过后，运行器允许模型回退到本次运行中的绿色补丁。父版与拟生成的子版具有相同的工具和预算。本轮的对照衡量在该运行器上更换技能版本的效果；上一轮没有这项工具，不能直接做跨轮收益比较。

## 学习、对照与门禁

1. 按独立学习批次执行，每个批次运行前冻结清单。第一轮在每道学习题上实际注入父版。优先选取发生合格执行失败、最终失败或耗尽预算的运行。若第一轮没有此类记录，完整重复该批次一次。两轮中只有已恢复的改写后公开测试失败时，以该类失败为证据，记录最终是否通过。若没有合格失败，流程在提案前结束。
2. GLM 收到父技能、本轮合格学习轨迹和经校验的补丁及测试事实。候选必须引用合格失败并实际改变有序步骤。生成最多允许一次因输出合同不合格而重试，随后固定单一候选。开发结果与独立测试详情均不作为提案输入。
3. 子版在产生修订的该批学习题上固定应用并重放，与各题首轮父版试用并列。分别记录模型调用公开测试时开、关节点的结果，是否保存源码有变化的绿点，以及是否主动将不同的当前源码恢复到绿点。学习重放不计入开发收益。
4. 在原始计数选项题和 Click #557 上使用正常语义路由，每题两次父子配对，第二次交换先后顺序。剩余开发分组、既有回归用例和技能家族的所有学习支持任务共同构成原门禁。三个开发分组中至少两个各有两次与技能行为相关的改善，同时要求零退化。若剩余分组已无法满足要求则提前结束。只有完整门禁通过才会运行两道未暴露的留出题，各重复两次。
5. 实验不自动发布技能。已完成的单臂和请求费用保留。单独的基础设施错误不作为工单评分。

## 可回退补丁的证据

开启 `Settings.public_checkpoints` 后，模型通过 `test` 或完整匹配的公开命令请求测试。控制器从当前沙箱导出全部可编辑源码，叠加冻结的原始输入，在新的容器中执行公开命令。测试通过才记录可恢复的源码哈希。模型可以用 `restore_checkpoint` 恢复本次运行的绿点，再继续修改或提交。任务耗尽时，系统保留真实终态，不从历史绿点中代为挑选提交。

报告区分模型是否触发公开用例、提交是否通过独立评测、是否保存了可回退的补丁，以及是否在修改后主动回退。对于任务预置的公开开关用例，模型运行套件不代表模型自己设计了这两条断言。计数选项题与 #557 的额外测试在正式评分关闭后运行，不给模型反馈。

## GLM 的实际修订

第二批的两道学习题各运行两次。父版四次均提交了通过独立评分的补丁，其中三次在修改后仍有公开测试失败。一次进度条修复只解决了隐藏状态，另一次进度条修复和一次着色帮助修复在中途都留下两个状态的失败。GLM 的一次提案引用了这三次运行，生成直接子版 `4a88b651b3`。两道焦点开发题的轨迹均未进入提案。冻结的证据及父子技能全文 `experiments/glm-click-procedure-002/revision.json`

操作步骤从七条变为九条。父版已有“提交前跑公开测试”的要求。子版进一步要求逐项读取同一次执行中开启与关闭的断言结果，后续修改导致回归时调用 `restore_checkpoint` 并重验。它还写进了进度条尾批处理和彩色文本宽度的具体做法；学习题重放可能受益于这些具体知识，迁移需要另行评估。

第七条步骤把一个例子写为“隐藏状态仍为 done=8，而同次开启状态通过”。已核对引用中的每一份改后补丁和相应公开测试。记录到隐藏状态为 done=8 时，两态均失败；另一个单态失败的场景是开启失败、隐藏通过。四次进度条改后检查中没有它声称的状态组合。技能摘要保持执行证据绑定，但自由生成的步骤仍可能夹带错误历史陈述。本轮保留原候选进行公平对照，该句不能用作历史事实。步骤原文与逐事件审计 `experiments/glm-click-procedure-002/step-claim-audit.json`

在同样固定注入技能的第二批学习题首遍，父版独立评分 2/2；子版重放 1/2。子版在两题上都将开启、关闭公开节点跑绿并保存了绿色源码，却在带颜色帮助文本的独立评分中失败。用八个公开输入分别运行原始、GLM 和上游修复后，六个输入与参考一致。在另外两个输入上，关闭颜色仍留下应去掉的控制序列，开启颜色时输出正常。这两例说明只运行两种开关取值，仍可能漏掉同一取值内的不同输入形态。学习补丁的三方 CLI 输出 `experiments/glm-click-procedure-002/learning-patch-probe.json`

## 开发对照与绿色补丁回放

每道题做两次正常路由配对。独立评分逐对如下。

| 任务 | 第一次父版 / 子版 | 第二次父版 / 子版 | 父版通过 | 子版通过 |
| --- | --- | --- | --- | --- |
| 计数选项 | 应用通过 / 应用通过 | 跳过通过 / 应用通过 | 2/2 | 2/2 |
| Click #557 | 路由不确定而未注入，失败 / 应用失败 | 应用失败 / 应用后耗尽 | 0/2 | 0/2 |

两组均没有单次或重复改善。原门禁需要至少两个开发分组各改善两次，剩余一个开发分组已无法补足，按协议停止。未运行留出题，未发布候选。正式结果和门禁 `experiments/glm-click-procedure-002/result.json`

#557 的子版两次都被注入。模型运行了任务附带的公开测试，两次均没有调用额外命令去检查禁用帮助的 CLI 输出。开发题保留了原始公开复现方式。与本轮学习题不同，开发复现没有预置两个具名开关节点。子版写下了要分状态检查的建议，却没有在这道新情形中自行补齐检查。四次运行有三份提交，在关闭帮助时都错误打印了 `Try "inspect --help" for help.`；另一次子版运行耗尽步数未提交。计数题四份提交均通过独立评分。七次提交的离线复验均重现原判定。逐个开发补丁和 CLI 输出 `experiments/glm-click-procedure-002/patch-probes.json`

两个批次共有 20 次真实 GLM 求解，19 次生成了内容已经更改且通过公开测试的可恢复补丁。模型主动调用回退为 0 次。从两批各取真实绿点，在独立 Docker 沙箱内按“绿 → 换回原始故障源码，红 → 通过生产接口恢复，绿”的顺序复验，恢复前后的绿色源码哈希相同。第二批选择的是子版带颜色帮助文本的学习补丁，它可准确回到公开测试绿色，同时保留了前述独立评分失败。这两项证据分别回答了能否保存恢复和模型是否主动使用。第一批回退回放 `experiments/glm-click-procedure-001/checkpoint-replay.json` · 第二批回退回放 `experiments/glm-click-procedure-002/checkpoint-replay.json`

两个批次共 222 次 GLM 调用，按本地计量配置估算已结算 527.22176 套餐积分，第一批为 118.56125，第二批为 408.66051。本轮新增未决预留为零。真实模型独立采样，样本来自一个仓库的开发任务；本轮没有新题收益估计。

## 执行入口

仓库根目录中已有归档。复核归档使用离线命令，首次准备和在线求解须使用未占用的实验目录，沿用同一 GLM 配置和账本。

```bash
study=experiments/glm-click-procedure-002
uv run --locked python scripts/report_click_procedure.py --root "$study" --output "$(mktemp -d)"
```

```bash
uv run --locked python scripts/run_click_procedure.py prepare --learn /path/to/new-learning-bundle/manifest.json --root experiments/glm-click-procedure-new
uv run --locked python scripts/run_click_procedure.py run --root experiments/glm-click-procedure-new
```

已暴露过的学习运行不再满足本协议的首次独立性检查。开展独立复制时应传入新的、经验证的学习清单和对应归档。复核已完成的实验不需要 GLM 密钥。
